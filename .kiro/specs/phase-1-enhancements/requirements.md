# Requirements Document

## Introduction

The UTCC Internship & Trip Management System Phase 1 Enhancements introduce three critical features to transform the system from basic functionality to production-ready: comprehensive application forms with document uploads, enhanced job details with Google Maps integration, and a complete document management system. These enhancements address current limitations where students can only click "Apply" without providing information, job details are insufficient for decision-making, and no document storage exists.

## Glossary

- **Application_Form_System**: The subsystem that collects and validates student application information
- **Document_Management_System**: The subsystem that stores, retrieves, and manages uploaded and generated documents
- **Job_Details_System**: The subsystem that displays internship position information including location and company details
- **Maps_Integration_Service**: The Google Maps API integration service that displays locations and routes
- **Student**: A user with STUDENT role who browses and applies for internship positions
- **Company**: An organization offering internship positions
- **Application**: A student's submission for an internship position including personal information and documents
- **Document**: A file (PDF, image, or ZIP) uploaded by users or generated by the system
- **Internship_Position**: A job posting created by a company offering internship opportunities
- **Screening_Question**: A custom question defined by a company for applicants to answer
- **UTCC**: University of the Thai Chamber of Commerce (reference location for distance calculations)

## Requirements

### Requirement 1: Application Form Data Collection

**User Story:** As a student, I want to submit comprehensive application information, so that companies can properly evaluate my qualifications.

#### Acceptance Criteria

1. WHEN a student clicks "Apply" on an internship position, THE Application_Form_System SHALL display a multi-section application form
2. THE Application_Form_System SHALL collect personal information fields: full name, phone number, email address, and physical address
3. THE Application_Form_System SHALL collect academic information fields: GPA, major, and current year of study
4. THE Application_Form_System SHALL validate that GPA is a decimal number between 0.00 and 4.00
5. THE Application_Form_System SHALL validate that phone number follows Thai mobile format (10 digits starting with 0)
6. THE Application_Form_System SHALL validate that email address contains @ symbol and valid domain
7. WHEN all required fields are completed, THE Application_Form_System SHALL enable the preview button
8. WHEN a student clicks preview, THE Application_Form_System SHALL display all entered information in read-only format
9. WHEN a student confirms submission from preview, THE Application_Form_System SHALL save the application with status PENDING
10. WHEN submission succeeds, THE Application_Form_System SHALL display a confirmation message with application reference number
11. WHILE an application has status PENDING, THE Application_Form_System SHALL allow the student to edit the application
12. WHEN a company changes application status from PENDING, THE Application_Form_System SHALL prevent further edits

### Requirement 2: Application Document Upload

**User Story:** As a student, I want to upload required documents with my application, so that companies have all materials needed for evaluation.

#### Acceptance Criteria

1. THE Application_Form_System SHALL require CV upload in PDF format with maximum size 5MB
2. THE Application_Form_System SHALL require transcript upload in PDF format with maximum size 5MB
3. THE Application_Form_System SHALL provide a cover letter text area with maximum length 2000 characters
4. THE Application_Form_System SHALL provide an optional portfolio URL field with maximum length 500 characters
5. WHEN a student selects a file, THE Application_Form_System SHALL validate file format matches allowed types
6. WHEN a student selects a file, THE Application_Form_System SHALL validate file size does not exceed maximum
7. IF file validation fails, THEN THE Application_Form_System SHALL display an error message specifying the validation rule violated
8. WHEN a student uploads a valid file, THE Document_Management_System SHALL store the file with unique identifier
9. WHEN file upload succeeds, THE Application_Form_System SHALL display file name and upload success indicator
10. THE Application_Form_System SHALL allow students to replace uploaded files before submission
11. WHEN application is submitted, THE Document_Management_System SHALL associate all uploaded files with the application record

### Requirement 3: Company Screening Questions

**User Story:** As a company, I want to ask position-specific screening questions, so that I can filter candidates based on my requirements.

#### Acceptance Criteria

1. WHEN a company creates an internship position, THE Job_Details_System SHALL allow adding screening questions
2. THE Job_Details_System SHALL support question types: short text (max 200 characters), long text (max 1000 characters), and single choice
3. THE Job_Details_System SHALL allow marking questions as required or optional
4. THE Job_Details_System SHALL allow up to 10 screening questions per position
5. WHEN a student applies for a position with screening questions, THE Application_Form_System SHALL display all questions in the application form
6. THE Application_Form_System SHALL validate that all required screening questions are answered before enabling preview
7. WHEN application is submitted, THE Application_Form_System SHALL save screening question responses with the application
8. WHEN a company views an application, THE Job_Details_System SHALL display screening question responses alongside other application data

### Requirement 4: Enhanced Job Information Display

**User Story:** As a student, I want to see comprehensive job details, so that I can make informed decisions about applying.

#### Acceptance Criteria

1. WHEN a student views an internship position, THE Job_Details_System SHALL display salary or allowance range
2. THE Job_Details_System SHALL display internship duration with start date and end date
3. THE Job_Details_System SHALL display application deadline date
4. THE Job_Details_System SHALL display benefits list as bullet points
5. THE Job_Details_System SHALL display internship type (full-time or part-time)
6. THE Job_Details_System SHALL display company contact information including email, phone, and LINE ID
7. WHEN salary range is not provided, THE Job_Details_System SHALL display "Negotiable" instead of empty field
8. WHEN benefits list is empty, THE Job_Details_System SHALL display "No benefits specified" message
9. THE Job_Details_System SHALL display all existing fields: title, description, requirements, location, mode, and available slots
10. WHEN application deadline has passed, THE Job_Details_System SHALL disable the Apply button and display "Application closed" message

### Requirement 5: Company Image Gallery

**User Story:** As a student, I want to see company photos and office images, so that I can understand the work environment.

#### Acceptance Criteria

1. WHEN a company creates or edits an internship position, THE Job_Details_System SHALL allow uploading up to 8 images
2. THE Job_Details_System SHALL accept image formats: JPEG, PNG, and WebP
3. THE Job_Details_System SHALL validate that each image does not exceed 3MB
4. THE Job_Details_System SHALL require at least one image (company logo) for each position
5. WHEN a student views a position, THE Job_Details_System SHALL display images in a gallery layout
6. THE Job_Details_System SHALL display the first image as the primary featured image
7. WHEN a student clicks on a gallery image, THE Job_Details_System SHALL display the image in full-screen viewer
8. THE Job_Details_System SHALL provide navigation controls (previous/next) in the full-screen viewer
9. WHEN images fail to load, THE Job_Details_System SHALL display a placeholder image with company name

### Requirement 6: Google Maps Location Integration

**User Story:** As a student, I want to see the company location on a map with distance from UTCC, so that I can evaluate commute feasibility.

#### Acceptance Criteria

1. WHEN a student views an internship position, THE Maps_Integration_Service SHALL display an embedded Google Map showing company location
2. THE Maps_Integration_Service SHALL place a marker at the company address coordinates
3. THE Maps_Integration_Service SHALL calculate and display straight-line distance from UTCC to company location in kilometers
4. THE Maps_Integration_Service SHALL display estimated travel time by car during typical morning commute hours (7-9 AM)
5. THE Maps_Integration_Service SHALL provide a link to open full directions in Google Maps
6. WHEN company address cannot be geocoded, THE Maps_Integration_Service SHALL display "Location unavailable" message and hide the map
7. THE Maps_Integration_Service SHALL use UTCC coordinates (13.7563° N, 100.5018° E) as the origin point for all distance calculations
8. THE Maps_Integration_Service SHALL display the map with zoom level showing both UTCC and company location when possible
9. WHEN a student clicks "Get Directions", THE Maps_Integration_Service SHALL open Google Maps with route from UTCC to company location

### Requirement 7: Document Storage and Retrieval

**User Story:** As the system, I want to securely store and retrieve documents, so that files are available when needed and protected from unauthorized access.

#### Acceptance Criteria

1. WHEN a document is uploaded, THE Document_Management_System SHALL generate a unique identifier (UUID) for the document
2. THE Document_Management_System SHALL store documents in the file system at path /uploads/{year}/{month}/{uuid}.{extension}
3. THE Document_Management_System SHALL store document metadata in the database including: id, filename, file type, file size, upload date, and uploader user id
4. THE Document_Management_System SHALL associate each document with its parent entity (application, student profile, or system template)
5. WHEN a user requests a document, THE Document_Management_System SHALL verify the user has permission to access the document
6. THE Document_Management_System SHALL allow access if the user is the document owner, the company reviewing the application, or an admin
7. WHEN access is denied, THE Document_Management_System SHALL return HTTP 403 Forbidden status
8. WHEN a document is requested, THE Document_Management_System SHALL set appropriate Content-Type header based on file extension
9. THE Document_Management_System SHALL set Content-Disposition header to inline for PDFs and images, and attachment for other types
10. WHEN a document file is missing from storage, THE Document_Management_System SHALL return HTTP 404 Not Found status

### Requirement 8: Document Version Control

**User Story:** As a student, I want to update my documents while maintaining history, so that I can improve my application materials without losing previous versions.

#### Acceptance Criteria

1. WHEN a student uploads a replacement document, THE Document_Management_System SHALL create a new document record with incremented version number
2. THE Document_Management_System SHALL mark the previous version as superseded and set superseded_at timestamp
3. THE Document_Management_System SHALL maintain the relationship between document versions using previous_version_id field
4. WHEN displaying documents, THE Document_Management_System SHALL show only the latest version by default
5. THE Document_Management_System SHALL provide a version history view showing all versions with upload dates
6. THE Document_Management_System SHALL allow users to download any previous version from version history
7. WHEN an application is submitted, THE Document_Management_System SHALL lock document versions and prevent further replacements
8. THE Document_Management_System SHALL retain all document versions for audit purposes even after newer versions are uploaded

### Requirement 9: System-Generated Documents

**User Story:** As faculty staff, I want the system to generate required documents from templates, so that administrative paperwork is automated and consistent.

#### Acceptance Criteria

1. THE Document_Management_System SHALL provide a recommendation letter template with placeholders for student name, position title, company name, and faculty signature
2. THE Document_Management_System SHALL provide an internship agreement template with placeholders for student details, company details, duration, and terms
3. THE Document_Management_System SHALL provide a certificate template with placeholders for student name, company name, duration, and completion date
4. WHEN faculty staff requests a recommendation letter, THE Document_Management_System SHALL populate the template with data from student profile and application
5. WHEN an application is accepted, THE Document_Management_System SHALL generate an internship agreement PDF with populated data
6. WHEN an internship is completed, THE Document_Management_System SHALL generate a certificate PDF with completion details
7. THE Document_Management_System SHALL store generated documents with document type: RECOMMENDATION_LETTER, INTERNSHIP_AGREEMENT, or CERTIFICATE
8. THE Document_Management_System SHALL associate generated documents with the related application record
9. WHEN a generated document is created, THE Document_Management_System SHALL send a notification to relevant users (student, advisor, company)
10. THE Document_Management_System SHALL allow faculty staff to download generated documents in PDF format

### Requirement 10: Document Viewer

**User Story:** As a company reviewer, I want to view uploaded documents within the application, so that I can review materials without downloading files.

#### Acceptance Criteria

1. WHEN a company views an application, THE Document_Management_System SHALL display a list of all uploaded documents with file names and types
2. WHEN a user clicks on a PDF document, THE Document_Management_System SHALL display the PDF in an embedded viewer
3. WHEN a user clicks on an image document, THE Document_Management_System SHALL display the image in a modal viewer
4. THE Document_Management_System SHALL provide zoom controls (zoom in, zoom out, fit to width) for PDF viewer
5. THE Document_Management_System SHALL provide page navigation controls (previous page, next page, page number) for multi-page PDFs
6. THE Document_Management_System SHALL provide a download button in the document viewer
7. WHEN a document fails to load in the viewer, THE Document_Management_System SHALL display an error message and provide a download link
8. THE Document_Management_System SHALL display document metadata (file size, upload date, version) below the viewer
9. WHERE the browser does not support PDF viewing, THE Document_Management_System SHALL provide a download button instead of embedded viewer

### Requirement 11: Application Form Validation and Error Handling

**User Story:** As a student, I want clear validation feedback, so that I can correct errors before submission.

#### Acceptance Criteria

1. WHEN a required field is empty, THE Application_Form_System SHALL display "This field is required" message below the field
2. WHEN a field value is invalid, THE Application_Form_System SHALL display a specific error message explaining the validation rule
3. THE Application_Form_System SHALL validate fields on blur (when user leaves the field)
4. THE Application_Form_System SHALL display error messages in red text with an error icon
5. THE Application_Form_System SHALL prevent form submission while any validation errors exist
6. WHEN all validation errors are resolved, THE Application_Form_System SHALL remove error messages and enable the preview button
7. THE Application_Form_System SHALL display a summary of all errors at the top of the form when user attempts to submit with errors
8. WHEN file upload fails due to network error, THE Application_Form_System SHALL display "Upload failed. Please try again." message with retry button
9. WHEN application submission fails, THE Application_Form_System SHALL preserve all entered data and display error message
10. THE Application_Form_System SHALL provide a "Save as Draft" button to save incomplete applications for later completion

### Requirement 12: API Endpoints for Phase 1 Features

**User Story:** As a frontend developer, I want RESTful API endpoints for Phase 1 features, so that I can integrate the new functionality.

#### Acceptance Criteria

1. THE Application_Form_System SHALL provide POST /api/v1/applications endpoint accepting application data and returning application id
2. THE Application_Form_System SHALL provide PUT /api/v1/applications/{id} endpoint for updating pending applications
3. THE Application_Form_System SHALL provide GET /api/v1/applications/{id}/preview endpoint returning formatted application data
4. THE Document_Management_System SHALL provide POST /api/v1/documents/upload endpoint accepting multipart file and returning document id
5. THE Document_Management_System SHALL provide GET /api/v1/documents/{id} endpoint returning document file with appropriate headers
6. THE Document_Management_System SHALL provide GET /api/v1/documents/{id}/metadata endpoint returning document information without file content
7. THE Document_Management_System SHALL provide GET /api/v1/applications/{id}/documents endpoint returning list of all documents for an application
8. THE Job_Details_System SHALL provide PUT /api/v1/internships/{id} endpoint accepting enhanced job details including salary range, duration, deadline, benefits, and contact information
9. THE Job_Details_System SHALL provide POST /api/v1/internships/{id}/images endpoint accepting image uploads and returning image URLs
10. THE Job_Details_System SHALL provide POST /api/v1/internships/{id}/screening-questions endpoint accepting question definitions
11. THE Maps_Integration_Service SHALL provide GET /api/v1/maps/distance endpoint accepting company address and returning distance from UTCC
12. THE Document_Management_System SHALL provide POST /api/v1/documents/generate/{type} endpoint accepting template data and returning generated PDF document id

### Requirement 13: Database Schema for Phase 1 Features

**User Story:** As a backend developer, I want database tables for Phase 1 features, so that I can persist the new data.

#### Acceptance Criteria

1. THE Application_Form_System SHALL extend the applications table with columns: phone, address, gpa, major, year, cover_letter, portfolio_url
2. THE Document_Management_System SHALL create a documents table with columns: id (UUID), filename, file_type, file_size, file_path, uploaded_by (user id), uploaded_at, entity_type, entity_id, document_type, version, previous_version_id, superseded_at
3. THE Job_Details_System SHALL extend the internship_positions table with columns: salary_min, salary_max, start_date, end_date, application_deadline, benefits (JSON array), internship_type, contact_email, contact_phone, contact_line
4. THE Job_Details_System SHALL create a position_images table with columns: id (UUID), position_id, image_url, display_order, uploaded_at
5. THE Job_Details_System SHALL create a screening_questions table with columns: id (UUID), position_id, question_text, question_type, is_required, choices (JSON array for single choice type), display_order
6. THE Application_Form_System SHALL create an application_responses table with columns: id (UUID), application_id, question_id, response_text
7. THE Document_Management_System SHALL create indexes on documents table for entity_type and entity_id columns
8. THE Document_Management_System SHALL create indexes on documents table for uploaded_by and uploaded_at columns
9. THE Job_Details_System SHALL create foreign key constraints from position_images to internship_positions
10. THE Job_Details_System SHALL create foreign key constraints from screening_questions to internship_positions

### Requirement 14: Google Maps API Integration

**User Story:** As a system administrator, I want Google Maps API properly configured, so that location features work reliably.

#### Acceptance Criteria

1. THE Maps_Integration_Service SHALL use Google Maps JavaScript API for embedded maps
2. THE Maps_Integration_Service SHALL use Google Maps Geocoding API to convert addresses to coordinates
3. THE Maps_Integration_Service SHALL use Google Maps Distance Matrix API to calculate travel time
4. THE Maps_Integration_Service SHALL store API key in environment variable GOOGLE_MAPS_API_KEY
5. THE Maps_Integration_Service SHALL restrict API key to allowed domains in Google Cloud Console
6. WHEN API quota is exceeded, THE Maps_Integration_Service SHALL display "Map temporarily unavailable" message
7. WHEN API request fails, THE Maps_Integration_Service SHALL log error details and display user-friendly error message
8. THE Maps_Integration_Service SHALL cache geocoding results for company addresses to reduce API calls
9. THE Maps_Integration_Service SHALL cache distance calculations for 24 hours
10. THE Maps_Integration_Service SHALL provide fallback to display address text when map cannot be loaded

### Requirement 15: File Storage Configuration

**User Story:** As a system administrator, I want configurable file storage, so that the system can scale and adapt to different deployment environments.

#### Acceptance Criteria

1. THE Document_Management_System SHALL support local file system storage as default storage backend
2. THE Document_Management_System SHALL read storage configuration from environment variables: STORAGE_TYPE, STORAGE_PATH, STORAGE_MAX_SIZE
3. THE Document_Management_System SHALL create storage directories automatically if they do not exist
4. THE Document_Management_System SHALL verify write permissions on storage path during application startup
5. IF storage path is not writable, THEN THE Document_Management_System SHALL log error and fail application startup
6. THE Document_Management_System SHALL enforce maximum total storage size configured in STORAGE_MAX_SIZE
7. WHEN storage limit is reached, THE Document_Management_System SHALL reject new uploads with HTTP 507 Insufficient Storage status
8. THE Document_Management_System SHALL provide storage usage statistics via GET /api/v1/admin/storage/stats endpoint
9. WHERE cloud storage is needed, THE Document_Management_System SHALL support configuration for S3-compatible storage
10. THE Document_Management_System SHALL sanitize uploaded filenames to prevent directory traversal attacks

### Requirement 16: Performance Requirements for Document Operations

**User Story:** As a user, I want fast document operations, so that the application feels responsive.

#### Acceptance Criteria

1. WHEN a user uploads a document under 5MB, THE Document_Management_System SHALL complete the upload within 10 seconds on a 10 Mbps connection
2. WHEN a user requests a document, THE Document_Management_System SHALL begin streaming the file within 500 milliseconds
3. WHEN a user views the application form, THE Application_Form_System SHALL load the form within 2 seconds
4. WHEN a user views an internship position with map, THE Job_Details_System SHALL display the page within 3 seconds
5. THE Maps_Integration_Service SHALL load the embedded map within 2 seconds after page load
6. THE Document_Management_System SHALL support concurrent uploads from up to 50 users without degradation
7. THE Document_Management_System SHALL generate a PDF document from template within 5 seconds
8. WHEN displaying a list of 100 applications, THE Application_Form_System SHALL render the list within 1 second
9. THE Job_Details_System SHALL load position images progressively, displaying page content before all images load
10. THE Document_Management_System SHALL implement streaming for large PDF files to avoid loading entire file into memory

### Requirement 17: Security Requirements for Document Access

**User Story:** As a system administrator, I want secure document access controls, so that sensitive student information is protected.

#### Acceptance Criteria

1. THE Document_Management_System SHALL require authentication for all document operations
2. THE Document_Management_System SHALL verify user identity using JWT token in Authorization header
3. WHEN a student uploads a document, THE Document_Management_System SHALL set the student as the document owner
4. THE Document_Management_System SHALL allow document access only to: document owner, company reviewing the application, assigned advisor, and system administrators
5. THE Document_Management_System SHALL log all document access attempts including user id, document id, timestamp, and access result
6. THE Document_Management_System SHALL prevent directory traversal attacks by validating file paths
7. THE Document_Management_System SHALL scan uploaded files for malware using antivirus integration
8. WHEN malware is detected, THE Document_Management_System SHALL reject the upload and log security incident
9. THE Document_Management_System SHALL set secure HTTP headers: X-Content-Type-Options: nosniff, X-Frame-Options: DENY
10. THE Document_Management_System SHALL generate signed URLs with expiration time for document downloads shared externally

### Requirement 18: Mobile Responsiveness for Phase 1 Features

**User Story:** As a student using a mobile device, I want Phase 1 features to work on my phone, so that I can apply for internships anywhere.

#### Acceptance Criteria

1. WHEN a student views the application form on a mobile device, THE Application_Form_System SHALL display form fields in single column layout
2. THE Application_Form_System SHALL use mobile-optimized file upload controls that access device camera and gallery
3. WHEN a student views an internship position on mobile, THE Job_Details_System SHALL display the map in responsive container that fits screen width
4. THE Maps_Integration_Service SHALL provide touch controls for map interaction (pinch to zoom, drag to pan)
5. THE Document_Management_System SHALL display document viewer in full-screen mode on mobile devices
6. THE Job_Details_System SHALL display image gallery in swipeable carousel on mobile devices
7. THE Application_Form_System SHALL validate that form inputs are large enough for touch interaction (minimum 44x44 pixels)
8. WHEN a student uploads a file on mobile, THE Application_Form_System SHALL show upload progress indicator
9. THE Job_Details_System SHALL load optimized image sizes for mobile devices to reduce bandwidth usage
10. THE Application_Form_System SHALL save form data to local storage to prevent data loss if app is backgrounded

### Requirement 19: Accessibility Requirements for Phase 1 Features

**User Story:** As a user with disabilities, I want Phase 1 features to be accessible, so that I can use the system independently.

#### Acceptance Criteria

1. THE Application_Form_System SHALL provide text labels for all form inputs with for attribute linking to input id
2. THE Application_Form_System SHALL announce validation errors to screen readers using aria-live regions
3. THE Document_Management_System SHALL provide alt text for all images in the gallery
4. THE Job_Details_System SHALL ensure map controls are keyboard accessible
5. THE Application_Form_System SHALL support keyboard navigation through form fields using Tab key
6. THE Document_Management_System SHALL provide keyboard shortcuts for document viewer controls (arrow keys for navigation, +/- for zoom)
7. THE Application_Form_System SHALL ensure color is not the only means of conveying validation errors (use icons and text)
8. THE Job_Details_System SHALL provide text alternative for map showing address and distance information
9. THE Document_Management_System SHALL ensure PDF viewer has minimum contrast ratio of 4.5:1 for text
10. THE Application_Form_System SHALL provide skip links to bypass repetitive navigation

### Requirement 20: Internationalization for Phase 1 Features

**User Story:** As a Thai student, I want the interface in Thai language, so that I can understand all features clearly.

#### Acceptance Criteria

1. THE Application_Form_System SHALL display all form labels, placeholders, and buttons in Thai language
2. THE Application_Form_System SHALL display validation error messages in Thai language
3. THE Job_Details_System SHALL support Thai language for all job detail fields
4. THE Document_Management_System SHALL display document type labels in Thai language
5. THE Application_Form_System SHALL format dates using Thai Buddhist calendar (B.E.)
6. THE Application_Form_System SHALL format numbers using Thai locale (comma as thousands separator)
7. THE Maps_Integration_Service SHALL display map labels and directions in Thai language when available
8. THE Document_Management_System SHALL support Thai language in generated PDF documents
9. THE Application_Form_System SHALL provide English language option via language selector
10. THE Job_Details_System SHALL store language preference in user profile and apply consistently across sessions
